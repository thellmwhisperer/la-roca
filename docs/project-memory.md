# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

- Run the canonical local gate with `make check`; inspect the Gherkin catalogue with `make accept-index`. That gate stops at the root module, so a change under `plugins/<name>/` also owes `make -C plugins/<name> check`.
- Branch protection on `main` requires every job name a completed CI run reports: `check`, `vector-plugin`, `vector-native-linux`, `vector-native-darwin`, `upgrade-homes`, and each `upgrade-gauntlet (<version>)` cell. Re-derive that list from a completed run when the matrix changes; do not guess labels.
- Per-domain acceptance lives under `features/<domain>/`; the Godog harness is enabled only by the `acceptance` build tag. A feature carrying a routing tag (`@journey`, `@data-split-oracle`) is excluded from its domain suite and driven by its own harness in `test/acceptance/`.
- [CONTRIBUTING.md](../CONTRIBUTING.md#build-and-test) owns DATA SPLIT oracle coverage, evidence handling, and the owner-review requirement for golden or harness changes.
- The slop gate ratchets over test code too, so new tests alone can fail `make check`: fold paired cases into one table-driven test rather than raise the ceiling in `.slop/`.
- [Read-only snapshot cleanup](operations.md#read-only-snapshot-cleanup) owns the no-copy read-only open and doctor leftover cleanup for abandoned `roca-read-only-snapshot-*` directories from older binaries.
- Public source, documentation, features, and fixtures are English-only; use unmistakably synthetic test data.
- Never add Sherpa-style navigational comment blocks or numbered section maps to any file; the owner forbids them repository-wide.
- Keep distribution ownership declarations centralized in `internal/distribution/cli/uninstall.go` (`ownedPaths`, the `~/.roca` plugin trees, and recovery-backup handling); archived custodial plugin data is the one tree a purge owns only after its own consent.
- Managed agent artifacts use the shared zones and schema-versioned registry in `internal/artifact`; installers register skill, prompt, and hook ownership, and `ownedPaths` consumes that registry rather than growing a second install inventory.
- Embedded skill sources and their `AGENTS.md` payload pin live in `internal/distribution/skill`; installation and reseeding orchestration lives in `internal/distribution/cli`. The user-facing lifecycle is owned by `docs/lifecycle.md`, while skill names, runtime paths, and measured seats are owned by `docs/mcp.md`.
- Vector retrieval is opt-in behind `features.vector` (off by default; the bundled companion is already installed). `docs/vector.md` owns the operator contract and `docs/releases.md` owns platform availability. Agents learn the mandatory hybrid loop (nearby rows, FTS census, SQL frame; inference only at the end) from the shipped `roca-operations` skill.
- Federated plugin manifests are owned by `internal/provider/plugin/manifest.go`: keep the engine database-neutral, attach plugin databases read-only through its in-memory hub, and compose semantic fragments through that package. Optional per-column vector declarations project to `vector-registry.json`; `plugins/vector/internal/vector/federation.go` owns generic delta generation, adjacent database sidecars, and routed query fan-out with same-model-only score merging. The resident corpus and ops declarations live in `internal/distribution/{rocacorpus,rocaops}/plugin.json`; cron keeps its legacy descriptor until its migration, and `plugininstall` must preserve every declared database across updates.
- The SQL-generation seat (`internal/provider/query/prompt.go`) must teach every queryable table's real columns, including FTS5 virtual tables, and state the closed world: only the listed tables are readable, and sqlite_master is not available. MATCH and bm25 take the bare FTS table name even when FROM is schema-qualified. The read-only gate creates attached virtual tables from inspected `Table.FTS5` metadata and records FTS and shadow ownership in its schema-scoped validation catalog; never infer FTS kind from a name suffix. Pin that with Validate() behavior tests, not parser internals.
- Verified executable-only plugin packages declare their kind and optional writable state directory in `plugin.json`; `internal/distribution/plugininstall` preserves that manifest-owned namespace across updates and supplies purge ownership. Keep them out of data-plugin discovery; the contract lives in `docs/plugins.md`. Executable naming is centralized in `plugininstall.ExecutableName`; the bundled vector plugin is `roca-vector`.
- Optional `companion` in `plugin.json` is the generic session-child seam: `roca mcp serve` execs the named file from the plugin directory with fixed argv, owns stdin/stdout, retries crashes with bounded backoff, and never searches PATH or takes serve down. Contract: `docs/plugins.md` and `docs/mcp.md`. Implementation: `internal/provider/plugin/companion.go` and `internal/distribution/mcpplug/companion.go`. The separate vector resident lifecycle is owned by [docs/mcp.md](mcp.md#1-roca-mcp-serve-the-mcp-over-stdio), with the shared MCP/CLI client in `pkg/vectorresident`.
- The bundled corpus has no feature flag: the CLI installs and attaches it for every command except `roca store`, whose `openStoreService` omits corpus custody so a memory write never touches it. New ingest and lexical indexing target its database, and historical core rows remain readable without an implicit migration. The seams live in `internal/distribution/cli/cli.go` and `internal/provider/service/{ingest,plugins}.go`.
- Redacted CLI/MCP call history dual-writes rotating JSONL and durable `roca-ops.db`; `internal/distribution/callhistory` owns segment-idempotent backfill and the parity gate before doctor uses ops, while `internal/distribution/logfile` keeps the public contract, redaction, JSONL rollback, and ingest/migration-only file streams. The schema and full contract live in `internal/distribution/rocaops/schema.sql` and `docs/operations.md`. `roca doctor --report` is the read-only, privacy-safe support snapshot; `docs/operations.md` owns that contract.
- The client identifier contract is owned by [docs/queries.md](queries.md#memory-identifiers-for-clients), with conversion in `internal/jsonid`. MCP output shape is owned by [docs/mcp.md](mcp.md), pinned by `internal/distribution/mcpplug/toon_contract_test.go`.
- The optional [roca-playground executable](https://github.com/thellmwhisperer/roca-playground) owns the provider platform, repairer, interpreter, playground and explore. `internal/distribution/cli/playground.go` owns core dispatch. Its repository owns the inference acceptance scenarios; [CONTRIBUTING.md](../CONTRIBUTING.md#build-and-test) owns paired validation mechanics.
- [Model providers](models.md) owns the optional playground provider, repair, authorization, and LIMIT contracts. Core retains the validation connection in `internal/provider/query/sqlgate`.
- [Authored-SQL table names](queries.md#table-names-in-authored-sql) owns the qualification contract; the entry point is `sqlgate.RejectUnqualified`, called from `Service.Exec`.
- The playground plugin owns local-binary isolation; core keeps its runner ingest guard in `internal/ingest/detection_test.go`. [Model providers](models.md) owns the isolation contract.
- Account exports are invocation-scoped: `roca ingest <path>` imports one extracted ChatGPT or Claude snapshot, while plain/nightly ingest resolves only live agent roots; the contract lives in `internal/distribution/cli/ingest.go` and `features/ingest/`. `ingest.WithExportPath` decides the vendor from the folder shape and refuses a directory that is neither, so no snapshot is diagnosed as the other vendor's. ChatGPT project membership is `gizmo_type=snorlax` plus the opaque `gizmo_id`; `gizmo_type=gpt` is a Custom GPT and not a project. Claude personal exports ingest project entities, docs, current `memories.json` surfaces, and the narrow `design_chats` join, and do not assign ordinary `conversations.json` items to a project. `docs/ingest.md` owns the operator-facing contract.
- Core schema adoption is additive: `data/schema.sql` is core's only schema, each bundled plugin owns its own outside adoption (`internal/distribution/{rocaops,rocacron,rocacorpus}/schema.sql`, applied idempotently on install by the shared `internal/distribution/bundledplugin` installer), and plugin-local DATA SPLIT state, custody memberships, and atomic resumable batches live in `internal/distribution/migrationledger`, which keys every lifecycle transition, batch, and membership by a stable migration name owning one destination, so several custody migrations coexist in one plugin database without counting, colliding with, or overwriting each other and a DATA-1 ledger adopts that in place on the next `Prepare`. The [bundled plugin custody contract](plugins.md#verified-packages-and-lifecycle) owns DATA-4 orphan imports. `internal/store/adopt.go` compares an existing core database against its schema and adds what is missing, so a new core column must be nullable with a constant default or adoption refuses it. Every pull request and release replays the frozen old-version homes through the current binary (`make upgrade-gauntlet`), and a release whose schema change an existing database must adopt freezes one more of them; `docs/releases.md` owns that definition of done.
- DATA SPLIT session history is copied only into the hidden digest-only version tables owned by `internal/distribution/corpusarchive`; exact payloads share physical version rows but retain a distinct custody membership for every legacy occurrence, divergent payloads remain versions, and legacy child IDs are evidence rather than identity. Version rows never duplicate harvest text. DATA-3 reconciles every frozen table and session by count and hash, including exchange provenance, and cutover requires an exactly 100% report. The currently served corpus tables remain untouched until cutover. Live harvest of a growing session file appends new exchanges from a per-session cursor; a genuine rewrite records one lineage digest without content.
- [Bundled ops custody](plugins.md#the-bundled-roca-ops-plugin) owns DATA-2 snapshot, resume, and empty-state semantics; implementation lives in `internal/distribution/rocaops/{memory_custody.go,schema.sql}`.
- [Architecture](architecture.md) owns DATA-6 routing and rollback; [migration operations](operations.md#explicit-data-split-migration) owns the explicit migration and readiness workflow. The service composes the compatibility main and lazy FTS indexes in `internal/provider/service/hub.go`.
- Every file parser is one line in the compiled-in `registry` (`pkg/parsers/registry.go`), declaring a destination (corpus, store, or both), a canonical harness, and never a file format; it owes a measured real-store shape plus a synthetic fixture folder under `pkg/parsers/testdata/conformance/`; the opt-in present-agent smoke (`ROCA_REAL_HARVEST=1`, deliberately outside `make check`) must prove material real yield, and `docs/agent-parsers.md` owns the contribution kit.
- Pi's complete private-store inventory is owned by `internal/ingest/{roots,scan}.go`, while `pkg/parsers/pi.go` owns the content projection: nested child sessions are corpus, and mission indexes, configuration, logs, packages, and runtime state remain named file-coverage exclusions. `docs/ingest.md` owns the operator-facing classification.
- Cursor's database readers share the WAL-safe snapshot seam in `internal/ingest/cursor.go`; agent-home normalization belongs to `pkg/parsers/cursor_store.go`, and legacy IDE normalization to `pkg/parsers/cursor.go`. `docs/ingest.md` owns locations, classification, and operator-facing behavior.
- Hermes sessions stay in `internal/ingest/hermes.go`; `MEMORY.md` blocks (identity = content hash, vanished = superseded) are `pkg/parsers/hermes_memory.go`. `session_model_usage`, `gateway_routing`, and `system_prompts` join onto already-read sessions as metadata, and `sessions.source` qualifies `source_surface` as `Hermes/<channel>`. Named exclusions and the mutability contract live in `docs/ingest.md`.
- The pre-federation adapter is `internal/ingest/legacy_store.go`; `docs/ingest.md` owns its operator-facing routing, identity, configuration, and reporting contract.
- Teaching a parser to read more of a source means bumping its reading version, in `parserVersions` (`internal/ingest/state.go`) for the established kinds or in the registry line's `Version` for a contributed one: the version rides in the watermark so a plain `roca ingest` re-reads synced files, and `internal/ingest/provenance_test.go` pins that the re-read backfills without duplicating.
- Per-exchange provenance is filled only from what a source itself recorded; a column NULL means the source said nothing, never zero. Use `parsers.UsageTally` rather than assembling `parsers.Provenance` by hand.
- OpenCode normalization is message-shaped in `internal/ingest/opencode.go`: every finished message owns one exchange and its recorded model, reasoning/tool/patch parts stay with it, todos live in session metadata, and step/event telemetry stays outside the corpus. Keep the `opencode-v9` watermark and source-ID rewrite path in sync when that projection changes.
- Records left out are reported apart: `parsers.Discard.ByDesign` is what this build never meant to read, and everything else is what it could not read. Collapsing the two is what made a healthy ingest report thousands of failures.
- Cron ride manifests are optional `rides.toml` plugin payloads; `internal/provider/plugin/rides.go` owns discovery, but only installer-manifested, checksum-verified payloads whose recorded consent is executable may contribute rides, because a declared ride is an execution surface and never data-only. The observer and canonical custodial journey database live in `internal/distribution/rocacron`, and the train probes but never holds the core log lock.
- The `docs/plugins.md` quickstart (`first-receipts`) is a copy-verbatim walkthrough hand-verified against the shipping binary: keep its steps working against a scratch `--db-path` database whenever the plugin surface changes, and keep its example names clear of the bundled `roca-corpus`/`roca-ops` seats.
