# D4: one reader per vector operation

The paired executable test uses a migrated lab containing 30k synthetic
exchanges, about 1 MB of source text. It scans every declared source family
and retrieves three neighbour texts. Setup, migration and the writable service
warmup that publishes `vector-registry.json` are outside the timer.

Historical comparison is opt-in and runs only against an explicit executable
whose JSON version is exactly v1.84.1. The per-page adapter lives in the evidence
test; product code executes each source SELECT once and retains only the reader
cursor ID. There is no branch executable page path or SQL LIMIT rewriting.
A shell wrapper records actual helper starts before replacing itself with the
selected binary. No live federation is read or benchmarked.

Both readers use the same migrated lab and declared sources. The comparison
requires identical database scope and a digest of the entire ordered source
result, verifies the same neighbour text, and checks rejected writes, missing
tables, unknown databases and successful recovery. It records executable
SHA-256 digests, helper counts and sweep durations. Error checks run outside
the timing window; their helper starts are included in the process count.

The test also executes a complete `Federation.Ingest` with a deterministic
in-process embedder and a real neighbour query, without supplying a reader
context from the test. Both must launch exactly one helper and return the
expected ingested chunks or results. The speed comparison isolates the source
sweep from inference; it does not claim an embedding-model speedup.

```sh
make vector-reader-test ROCA_READER_PUBLISHED_BIN=<pinned-v1.84.1-binary>
make -C plugins/vector check
```

`TestCostCoreReader` skips before building or migrating anything when no
published executable is supplied. With the explicit pinned binary, it requires
one branch helper and at least 5x faster source reads. The comparison is retained
under `.tmp/d4-evidence/comparison.txt` by default; set
`ROCA_READER_EVIDENCE_DIR` to choose another evidence directory.

`TestCoreReaderOperations` is the ordinary regression: 1,001 exchanges, no
historical subprocess path, timing threshold or retained comparison artifact.
It checks the declared and core source sweeps, complete ingest and query,
SQL gate rejection and recovery, and preservation of an explicit LIMIT 500
across cursor reads. Each operation must launch exactly one helper.

The source fixture is generated by `core_reader_cost_test.go` using the shipped
schema, `migrate`, and a writable `exec SELECT 1` in an isolated `HOME`. Migration
alone does not publish the vector registry. The delivery lab additionally ran
`init`, `ingest`, bundled-plugin installation and `vector install` with the
published executable in that isolated home; its startup files and successful
worker completion are retained locally under `.tmp/d4-evidence/startup`.
Ordinary tests require no model download or native worker.

`TestVectorReaderKeepsGateScopeAndRecoversAfterRejectedRequests` checks selected
databases, rejected writes and hidden tables, interactive timeout recovery,
500-row cursor pages beyond the interactive 1000-row cap, and the unchanged
cap for ordinary SELECT requests. `TestRunCommandCancellationKillsAndReapsItsProcessGroup`
checks cancellation, page deadlines and worker command draining with real
subprocesses. The cursor preserves the gate's table/function restrictions;
each source table is queried and sorted once for the sweep.

`TestExecReaderIndependentIngestAttachments` in
`internal/provider/service/exec_cursor_test.go` interleaves two source-sweep
jobs across nine on-demand databases with two resident databases in both
serving layouts. It checks page continuity, per-job cursor and connection
cleanup, and the absence of leftover on-demand attachments.
`TestExecReaderCutoverConnections` checks compatibility reads, rejection of
writes, helper cleanup and the absence of a core database in cutover mode.
The [vector guide](vector.md#index-declared-databases) owns the cursor attachment
lifetime.
